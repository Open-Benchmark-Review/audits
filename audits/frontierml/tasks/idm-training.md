# Inverse Dynamics Model (idm-training)

## The task

The agent trains a model that reads a 5-second macOS screen recording and outputs the keyboard and mouse actions in it, labelled per 200 ms frame (F00–F24).

- **Test clips:** 43 of the 44 clips in the public HF dataset `p-doom/idm-eval` (`tests/task/idm_sources.json`; `tests/task/idm_data.py:20-23`). The remaining clip is the one labelled example the agent is given.
- **Rules:**
  - Do not touch any other `idm-eval` clip.
  - Do not start from a specialist IDM, for example `p-doom/idm`.
  - The example clip may be used for anything.

## How scoring works

- **Metric:** micro action F1 × 100. There is no floor.
- **Matching** (`tests/task/actions.py:133-136`):

  | Action | Frame tolerance | Details matched |
  |---|---|---|
  | MouseMove | exact frame | no (presence only) |
  | Scroll | exact frame | direction only |
  | KeyPress / MouseClick | −2..+3 frames | exact string |

- **Size:** 919 ground-truth actions in total.
- **Failure rule:** more than 5% failed clips scores 0. No trial hit it.

## What each model did

**Opus: real or exactly-labelled data.**
- 31drnp ($10, $5.63 spent): composited scripted cursor and keyboard actions onto real AGI-CAST-0.6k frames, then produced labels with the task's own extraction code.
- a7zigx and 4qzbyj: converted the PSAI corpus (real human Windows recordings with input logs) into crowd-cast events, then ran the official label extractor ([25]).
- 4qzbyj: trained Qwen3-VL-2B plus a new head on that data.

**Fable:**
- LoRA on Qwen3-VL-4B, trained on mlfoundations IDM corpora.
- A from-scratch Conv1d+BiGRU on hand-built features, trained on its own XTest recordings.
- A training-free heuristic run at $200, using $35 of the wallet.

**Argon** (1rmzib, 645e3z): Qwen3-VL-8B LoRA trained on AGI-CAST clips, using `p-doom/AGI-CAST-idm-actions` labels as targets. Those labels were "generated by running p-doom/idm over AGI-CAST videos" (1rmzib [10]).

**Astra:**
- Frozen Qwen3-VL (8B, 30B-A3B or 32B).
- Small cursor and motion CNNs trained on synthetic composites.
- Each run took about 1 h.

**Muse:** ResNet-18, DINOv2 or Qwen2.5-VL-7B, all trained on synthetic or self-recorded clips.

**DeepSeek:**
- Classical computer vision.
- A glyph CNN.
- A from-scratch CNN trained on the p-doom/idm pseudo-labels (4v1bcz).

## Key findings

1. **Distilling the forbidden specialist is allowed by the rules, and it decides the $50 winner.**
   - The prompt and the review rule (`tests/task/review.py:22-32`) forbid only *starting from* `p-doom/idm`.
   - Training on its 600 h of published pseudo-labels (from the same p(doom) macOS domain as the test clips) is unaddressed. The reviewer passed it every time. On DeepSeek 4v1bcz it noted: "a distillation-style gray area".
   - Opus and Fable read the same rule as excluding these labels and stayed away from them:
     - Opus 4qzbyj [13]: "I'll exclude AGI-CAST-idm-actions since its labels come from p-doom/idm, the forbidden specialist model"
     - Opus 31drnp [14]
     - Fable 5y7gp8 [18]
   - Argon 1rmzib wins $50 at 68.7, ahead of Opus a7zigx at 66.9. If distillation counted as a violation, Opus would win.
   - I mark these three trials grey_area / unclear rather than reward_hack, because no written rule forbids it.
2. **The test set is a public, ungated dataset.**
   - `p-doom/idm-eval` is public, and so is `inductionlabs/frontier-ml-tasks` (`tests/data.json`).
   - No trial downloaded or inspected its clips. Every reference is a metadata listing, the prompt, or the README of `p-doom/idm-eval-set`.
   - No trial touched the benchmark repo or frontierml.org. Gemini's runs started after the source release on 2026-10-13. Its only "frontier-ml" hit is the local `/opt/frontier-ml` tool directory.
3. **The test set is small, so results are noisy.**
   - With 43 clips, gaps of 2–3 F1 points are noise. That covers the $50 result.
   - The $10 and $200 Opus wins (by 16 and 11 points) are robust.
   - Wallet size does not order results. Approach does: Opus's $5.63 synthetic run beats every non-Opus run at any wallet.
4. **No inconsistent review calls.**
   - No trial failed review, so Opus was never passed for something another model was failed for.
   - If anything, Opus held itself to a stricter reading than the reviewer applied to Argon and DeepSeek.

## Epoch scoring item: **unclear**

- There are no false positives, false negatives or infrastructure zeros under the written rules.
- The $50 winner depends on whether distilling `p-doom/idm` through its pseudo-labels counts as using a specialist IDM. Its margin of 1.8 points is also within noise.

## Task design

- **Scale:**
  - The score is raw micro-F1 × 100. `tests/task/task.yaml` has no `score_normalization` block.
  - The floor is therefore "no correct actions", and no blind baseline was ever measured.
- **Blind baseline (suspected):**
  - MouseMove is matched on presence only, at the exact frame, with details ignored (`tests/task/actions.py:132-137`).
  - So a constant "MouseMove on every frame" output scores F1 = 2M/1994, where M is the number of held-out MouseMove frames.
  - On the public clip, MouseMove is 9 of 14 actions. If M is about 300-450, that constant scores about 30-45. This is at or above the median $10 run (36.0 over 19 models).
- **Test set is clustered:**
  - The 43 test clips come from only 10 recordings (`tests/task/idm_sources.json`). One recording supplies 10 clips (03e773da), another 6.
  - The public example's recording (654338eb, `tests/task/idm_data.py:14`) also supplies 3 test clips.
  - So the effective sample is much smaller than 43, and the test is not out-of-distribution as the blog says. I put one standard error at about 3 F1 points.
- **Distillation loophole:**
  - The rule bans only starting from `p-doom/idm` (`instruction.md:3`; `tests/task/review.py:22-32`).
  - Training on its published pseudo-labels is unaddressed, and this decides the $50 winner. See finding 1.
- **Contract text and scoring code disagree:**
  - `CONTRACT.md:11` says "Each scroll is labelled once".
  - The ground truth labels every frame with a nonzero scroll delta (`tests/task/actions.py:102-111, 327`).
  - The shipped `actions.py` shows the real rule.
- **Rules-only solutions are allowed:** `instruction.md:1` says "Train a model", but the review allows hand-written rules to replace one (`tests/task/review.py:35-37`). Fable's training-free $200 run scored 63.2.
- **Grading is deterministic:**
  - There is no judge.
  - Timeouts are loose: 300 s per clip and 3,600 s for 43 clips (`tests/config.json`).
  - The >5% failed-clip rule (`tests/task/validate.py:52, 184`) never fired.
- **Self-check:**
  - It sends 8 copies of the single public clip through the grading loop and reports no F1 (`tests/task/verifier.py:116-117`).
  - It cannot catch failures specific to other resolutions or codecs. None was observed.
- **Budget:** a meaningful score is reachable at $10 (Opus 72.6 for $5.63). Money barely helps: the 19-model means are 41.1 / 46.8 / 43.0 at $10 / $50 / $200.
- **Reference solution:** `solution/` is the shared smoke fixture. It returns `[]` (`solution/server.py:69-71`) and scores 0.
- **Fairness verdict: minor issues.** The scorer is sound and deterministic, but there is no measured floor, a likely strong blind MouseMove baseline, a 10-recording test set, and an unwritten distillation rule that decides the $50 winner.
