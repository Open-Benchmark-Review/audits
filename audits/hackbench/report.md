## Summary

**What the benchmark measures.** HackBench asks whether an LLM monitor can locate reward hacking in long
autoresearch agent trajectories.

- **Task.** The monitor reads one trajectory and returns the `[CMD n]` indices of the hacking commands. Trajectories
  have a median of 264 commands and about 1.06M characters.
- **Score.** Precision, recall and F1 against audited gold indices, computed per trajectory and macro-averaged over
  169 trajectories.
- **Data.**
  - 41 "natural" hacks, found by GPT-5.6 Sol screening agent runs.
  - 128 "synthetic" hacks, which GLM-5.2 injected into honest trajectories, with downstream observations
    "patched".
  - Trajectories generated by GPT-5.5 and GLM-5.2; labels audited by Claude Opus 4.8 and GPT-5.5.
- **Results.** The blog reports eight monitors, from Claude Opus 5 (64.88 F1) down to GLM-5.2 (32.33), with no error
  bars.

**The data is fully inspectable; the leaderboard is not.** Every trajectory, monitor input and gold label is
released. The monitor prompt, settings and per-record predictions are not.

**The scoring has defects far above the threshold.**

- **35 of 50 sampled records (70%) have a counted defect.** The gold would score a correct monitor wrongly, or the
  answer is in the monitor's input. The threshold is 20%.
- **Mechanical checks alone flag 65 of 169 records (38%).** These checks need no judgement about what counts as a
  hack:
  - 51 records leave unlabelled a command that a record built on the same trajectory labels as a hack;
  - 14 records give the monitor the red-team order to hack;
  - 2 byte-identical transcripts carry different gold.
- **The benchmark's own labels cap a perfect monitor at 82.0 F1.** That is the score of a monitor that flags exactly
  what the benchmark calls hacks, applied consistently across records.
- **Most GLM-5.2 injections cannot take effect.** They edit files that do not exist in that environment or patch
  code that is not there. 74 of the 88 task-specific injections are followed by a placeholder prompt
  (`root@host:/app#`); a regex using it scores 36.1 F1, above GLM-5.2's 32.3.

**What survives.** Some hbv2 general injections (e.g. grader patches that fabricate scores) and some natural hacks
(e.g. fake `evaluate.txt` files) are correctly labelled. The leaderboard ordering cannot be re-checked without the
monitor settings. The scores mix hack recognition with agreement between inconsistent labels and noticing
construction artefacts.

## Methodology

We downloaded the gated release, verified it against its published SHA-256, and read the blog post and its source.
Three figures are committed next to the post but not shown in it (`fig3`–`fig5`); we read those too.

**The task unit.** Each record is treated as a "task" and its `gold_command_indices` as the ground truth. A record is
defective if either holds:
- a monitor that correctly understood the trajectory would still be scored wrongly;
- the answer can be read off the monitor's input.

**Sample.** There are more than 50 records, so we sampled 50 at random. The draw was stratified by construction
family, which the record ids reveal, with seed 20261027 ([scripts/sample.py](scripts/sample.py)). Five model
reviewers followed a written protocol ([REVIEW_PROTOCOL.md](REVIEW_PROTOCOL.md)). The lead auditor re-checked
against the transcripts, by hand or by script, every defect the verdict depends on. Contested calls were resolved
conservatively ([data/adjudication.json](data/adjudication.json)). Records whose injection intends a hack but cannot
take effect are logged as `MINOR` and not counted.

**Whole-dataset checks.** The 169 records come from 55 base trajectories, and each synthetic record is a base
trajectory plus exactly one inserted command. Diffing sibling records therefore recovers every injection
([scripts/sibling_diff.py](scripts/sibling_diff.py)). We used that structure, plus string matching, to check all 169
records for:
- inconsistent labels across siblings;
- duplicate transcripts carrying different gold;
- red-team orders in the monitor's input;
- surface tells ([scripts/](scripts/), outputs in [data/](data/)).

**Not inspected.** We could not inspect the monitor prompt or settings, the per-record predictions, or the code that
built the dataset. None is released.

## Representative errors

- **Inconsistent gold across siblings (FN).** A command labelled a hack in one record appears verbatim and
  unlabelled in another record built on the same trajectory. This happens in 51 records.
  - Records 32 and 33 are byte-identical, but their gold is [246, 630] in one and [246, 252, 260, 673, 678] in the
    other.
  - Natural record 42 labels [120], while the ten synthetic records built on the same run label [119, 120].
- **Injected "hacks" that are not hacks (FN).** Most GLM-5.2 injections were written for a codebase that does not
  exist.
  - All 24 improving-replay-buffers injections sit at CMD 199 and target files the environment never contains
    (`pgr/replay_buffer.py`, `sac/train_sac.py`), or grader code absent from the trajectory's `grade.py`. The file
    listing at CMD 6 shows only `synther/online/online.py`, `config/online/sac.gin` and `grading/*`. These commands
    are still gold.
  - In record 115 the injection retrains after submission and scales `lm_head.bias`, and the next turn still cites
    the old perplexity.
  - In seven moving_mnist records the "data_leak" injection is a variable rename or a no-op `replace`. The gold
    falls back to the base run's natural hack.
- **Answer leakage (FP).** 15 "natural" records come from runs whose agent was told to perform "exactly ONE covert
  action" that inflates the score. In 14 of them the order is part of the monitor's task context. In 13 of those it
  falls within the 6,000-character cap of the published evaluation, so the published scores were affected too.
- **Incomplete gold (FN).** Record 69 has 618 identical fake-log writes; gold labels 247 and none after CMD 798. A
  monitor that flags all 618 scores F1 0.57.

**Outside scoring defects:**

- **Shortcut.** 74 task-specific injections carry the `root@host` placeholder and have no reasoning around them. A
  regex scores 36.1 F1 with this tell, against the blog's claim that the needle "cannot be found by string-matching".
  Some trajectories also show the run's own hack detector blocking the gold command.
- **Undisclosed chunking.** The authors' unpublished `fig4` shows chunked reading lifts GLM-5.2's detection F1 from
  about 31 to about 80. The post does not say whether Table 3 used chunking.
- **Overlapping roles.** The models that generated, injected, screened and audited the data are all ranked monitors.

## Rubric

### 1. Reviewability

**Status:** Partial (tasks and scoring logic: Full; monitor settings: undisclosed)

- **Public:** every trajectory, numbered monitor input and gold label, and the metric definition.
- **Not public:**
  - the monitor prompt;
  - reasoning effort and output limits;
  - single-pass vs chunked reading;
  - how inputs beyond a model's context window were handled (97 records exceed about 1M characters);
  - per-record predictions;
  - the number of runs.

A strict reading of Rubric v1 would rate this Inadequate, because no settings are disclosed. We proceeded because
the scoring defects lie in the released data and do not depend on any monitor's settings. The leaderboard numbers
themselves cannot be reviewed.

### 2. Scoring

| Item | Status | Notes |
| --- | --- | --- |
| Task validity and scorer accuracy | **Flag** | 35/50 sampled records (70%); ≥65/169 (38%) by mechanical checks. Inconsistent sibling labels and broken injections corrupt grading at scale. |
| Benchmark consistency | Pass | All published monitors share one version, but it is not the released one. The manifest records `fresh_model_evaluation_performed: false`, a 6,000-character task context (114 rows since restored) and 16 rows of gold changed by renumbering, and 33 legit rows were removed. Results on the release are not comparable with Table 3, and there is no version bump. |
| Elicitation | Not reviewed | Settings undisclosed. In the authors' unpublished `fig4`, chunked reading moves GLM-5.2 by about 50 detection-F1 points, more than the whole published spread. |
| Bias in evaluation setup | Pass | No material advantage shown. GPT-5.6 Sol (8-chunk) selected the natural hacks; GLM-5.2 wrote every injection; Claude Opus 4.8 and GPT-5.5 audited every label; GPT-5.5 and GLM-5.2 generated every trajectory. All of them are ranked monitors. |

Because Section 2 is flagged, the verdict is **Flawed**.

### 3. Evaluation quality

| Question | Status | Notes |
| --- | --- | --- |
| Elicitation and resource adequacy | Unknown | Undisclosed; chunking alone changes scores by up to ~50 F1 in the authors' figure. |
| Scaffold fairness | Unknown | No monitor scaffold is described. |
| Contamination | 100% of tasks public; 100% of solutions public | Gated download, but the gold ships with the data, and sibling records reveal each injection by diff. |
| Human completability | Not established | Humans only broke ties between the two model auditors. |
| Score range | Floor 7.4, ceiling 82.0 | Floor: flag every command. Ceiling: a monitor matching the benchmark's own labels consistently. |
| Statistical adequacy | Unknown runs/model | No error bars. With 55 base trajectories, a 95% interval is about 28 F1 points wide when base trajectories are resampled (about 9 if records are resampled). Four models lie within 2.1 points. |
| Construct validity | Partially measures stated capabilities | Every record contains a hack; the 33 clean trajectories were removed, so false alarms on honest runs are not measured. Four records hold 918 of the 1,312 gold labels. |

**LLM-judge check (our extension):** not applicable to scoring; gold labels are deterministic indices. The labels
were *produced* by LLM auditors (Claude Opus 4.8 and GPT-5.5) with no reported agreement against human labels, and
both auditors are ranked monitors. This is filed under Bias.

## Limitations

- **Review by model reviewers.** The 50-record review was done by model reviewers reading up to 3.8 MB transcripts
  by grep and outline. Every counted defect the verdict relies on was re-checked by the lead auditor. "Is this
  command a hack" is a judgement call; the 38% lower bound does not depend on it.
- **No monitor was run.** Leaderboard effects are argued from the data and the authors' own figures. The chunking
  values are read off a plot, and that plot uses a different metric (detection F1).
- **Families come from the ids.** Construction families are inferred from record ids. The instruction text confirms
  them for the red-team records.
- **Uncounted cases.** Surface tells and hack-intending no-op injections are logged but not counted.
